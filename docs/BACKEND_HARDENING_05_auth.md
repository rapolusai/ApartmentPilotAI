# Backend hardening 05 — auth and audit (branch `APAI5-auth`)

Backend only. No Android, layout or reference HTML changes. Response shapes change only additively (`pinChangeRequired` on login; `actor` text where it used to be `null`); status codes change only where a fix needs it (429 + `Retry-After` for login locks, 409 for replayed edit keys and last-Admin changes, 400/404/405/415 instead of 401 for framework client errors). V1–V10 are untouched.

Base: `main` @ 7387b10 (APAI1 hardening). Implements the approved proposal `proposals/pin-login-hardening.md` with its recommended decisions, items 1–3 of `plans/audit-and-cleanup-plan-2026-10-08.md`, and the bugs/gaps below.

## Decisions and limits
- **Thresholds** as proposed and configurable. **Legacy short PINs** are flagged only (`pinChangeRequired`); no refusal cutoff.
- **Concurrency test wording:** the proposal listed "30 parallel wrong attempts → exactly 30 failures recorded". Because requests during a lock are free by design, the guard admits exactly 5 and refuses 25 with 429; the test asserts that (5 failures recorded, no bypass). The per-IP spray test asserts 30 admitted in parallel and the 31st refused.
- **Bean-validation message** keeps the existing `field: message` format, so register/join show `pin: Use a six-digit PIN.`.
- **Distributed lockout** of up to 15 minutes remains possible, as the proposal states; a second factor or trusted-device token needs Android work.
- **Rejected applicant in another apartment** still gets 409: moving a user row between tenants would drop it from the first apartment's member history. A rejected applicant who forgot the PIN also still needs the Admin. Resubmission with a legacy 4–5 digit PIN is no longer possible (join now needs six digits), as the proposal accepted.
- **Edit keys stored before this change** for the newly bound endpoints have the old fingerprint; retrying such an in-flight edit across the upgrade returns 409 instead of the old result. No stored data is rewritten.
- `/audit` without parameters keeps the old query; only `actor` text for rows without a person changes from `null` to `Automation` / `Provider` / `Security`, as planned. Android "Load more" and a filter are not included (needs UI approval).
- Rollback: `app.login-guard.enabled=false` or revert the branch. V11 only adds a table and can stay.
